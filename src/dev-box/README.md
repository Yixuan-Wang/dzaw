# dev-box

Personal ML development image: CUDA 13.0 + cuDNN (devel), Ubuntu 24.04, system Python 3.12, the packages in `requirements.in` installed with uv, and the shell tools from [dev-tools](../dev-tools/README.md) (fish, tmux, fzf and others) in `/opt/dev-tools/bin`.

## Files

- `requirements.in`: top-level dependencies. Add new Python dependencies here.
- `requirements.txt`: the lockfile generated from `requirements.in` during the lock stage. *Do not edit this file directly, but regenerated lockfile should be commited*.
- `dev-box.Dockerfile`: multistage Dockerfile with `dev-tools`, `base`, `lock`, `lockfile` and `dev-box` stages. The `dev-tools` stage uses the image named by `ARG DEV_TOOLS`.

## Build

### Lock 

This step is required only after editing `requirements.in`.

```sh
docker buildx build -f dev-box.Dockerfile --target lockfile --output type=local,dest=. .
```

This resolves `requirements.in` inside the image's platform (Python 3.12, CUDA 13.0 torch wheels) and writes `requirements.txt` here.
To force a fresh resolve, add `--no-cache-filter lock`.

### Build

```sh
docker buildx build -f dev-box.Dockerfile --target dev-box -t tyxw-dev-box:$(date +%Y%m%d) --load .
```

This installs Python dependencies pinned in `requirements.txt`. It also depends on the dev-tools image, so build that first (see [dev-tools](../dev-tools/README.md)). 
To use a different set of dev-tools, add `--build-arg DEV_TOOLS=tyxw-dev-tools:<date>`.

The tools are installed after the Python dependencies.

## Execution

### Docker

Requires the NVIDIA Container Toolkit on the host.

```sh
docker run --rm -it --gpus all tyxw-dev-box:20260925
```

Use the following example snippet to verify that PyTorch can see the GPU:

```sh
docker run --rm --gpus all tyxw-dev-box:20260925 \
    python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

### Apptainer

To use Apptainer, we need to convert the Docker image to SIF. 
```sh
# From the local Docker daemon into a SIF.
apptainer build ../../dist/tyxw-dev-box_20260925.sif docker-daemon://tyxw-dev-box:20260925

# From a Docker tar into a SIF.
# docker save tyxw-dev-box:20260925 -o dev-box.tar
apptainer build ../../dist/tyxw-dev-box_20260925.sif docker-archive://dev-box.tar
```

To run the container, add `--nv` for GPU access:

```sh
apptainer run --nv ../../dist/tyxw-dev-box_20260925.sif                  # python3.12
apptainer run --nv ../../dist/tyxw-dev-box_20260925.sif python train.py  # arguments replace CMD, as in Docker
```

Differences from Docker:

- The image filesystem is read-only and run 7under your own user, so `uv pip install --system` doesn't work inside it. Use `uv pip install --user`, or `--writable-tmpfs` for temporary changes. For permanent modifications, add it to `requirements.in` and rebuild.
- Your host `$HOME` is mounted, so any packages in `~/.local/lib/python3.12/site-packages` will override the image's.
